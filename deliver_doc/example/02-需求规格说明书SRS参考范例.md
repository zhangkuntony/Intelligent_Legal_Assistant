# 《人工智能大模型数据训练系统需求规格说明书（SRS）》

## A. 引言、项目范围与约束

* **项目名称**：人工智能大模型数据训练与考评系统

* **目标**：建立端到端的数据训练平台，覆盖 **数据采集 → 清洗预处理 → 模型训练 → 考评监控 → 报告生成** 全流程，提升训练质量与效率。

* **约束条件**：
  
  * 部署环境需支持分布式与容器化，默认仅支持 CPU/GPU 本地集群，不依赖外部商用云。
  
  * 数据需符合企业内部安全与隐私保护要求，禁止外泄。
  
  * 系统支持至少 **1000 并发用户**，响应时间 ≤ 2 秒。

* **评测维度**（在验收章节落地）：
  
  1. 可运行性（端到端流程跑通）
  
  2. 数据与模型检索的相关性与完整性
  
  3. 训练与考评指标（准确率、召回率、F1 等）正确性
  
  4. 引用与日志的准确性
  
  5. 系统鲁棒性（异常输入能优雅失败）

* * *

## B. 总体流程与关键能力映射

* **端到端流程图**（文本化）：
  
  ```
  数据源 → 采集 → 预处理 → 存储 → 模型训练 → 考评 → 报告生成 → 可视化展示
  ```

* **能力→章节映射表**

| 能力    | 落点章节                |
| ----- | ------------------- |
| 数据采集  | FR-01 数据管理需求 / 数据规范 |
| 数据预处理 | FR-02 清洗与预处理        |
| 模型训练  | FR-03 模型训练管理        |
| 资源调度  | NFR 性能需求            |
| 考评体系  | FR-04~FR-06 考评与评估   |
| 安全保障  | NFR 安全性需求           |
| 输出与报告 | FR-07 统一输出 / 接口规范   |
| 用户交互  | FR-08 CLI/HTTP 接口   |

* **设计取舍**：采用 **分布式训练 + 微服务架构**，数据存储混合使用 HDFS+MySQL+Redis，检索以向量索引为主，支持 BM25 混合检索。

* * *

## C. 功能性需求（FR）

每条功能需求需描述、输入输出、异常与验收标准。

1. **FR-01 数据管理**
   
   * 输入：CSV/JSON/图像/文本
   
   * 输出：标准化存储至分布式数据库
   
   * 验收：能从 ≥3 种不同数据源导入并统一字段，支持版本管理。

2. **FR-02 数据清洗与预处理**
   
   * 功能：去噪、缺失值填充、归一化、特征提取
   
   * 异常：缺失率 >30% 数据需报警
   
   * 验收：清洗前后对比报告生成。

3. **FR-03 模型训练管理**
   
   * 功能：支持 TensorFlow/PyTorch 框架，多 GPU 并行训练，断点续训
   
   * 输入：预处理后的数据
   
   * 输出：训练好的模型（ONNX/SavedModel）
   
   * 验收：10GB 数据集在 ≤30min 内完成训练。

4. **FR-04 考评任务与指标体系**
   
   * 功能：准确率、召回率、F1、AUC、资源消耗
   
   * 验收：评估报告含 ≥5 项核心指标，自动化生成。

5. **FR-05 评测与反馈**
   
   * 支持人工+自动混合评测，异常情况触发告警。

6. **FR-06 数据分析与可视化**
   
   * 功能：趋势、对比、异常检测；仪表盘可视化
   
   * 验收：用户可在 Web 界面生成对比图。

7. **FR-07 统一输出格式**
   
   * 输出 JSON：
     
     ```json
     {
       "result": "...",
       "metrics": {"accuracy":0.92,"f1":0.89},
       "citations": ["dataset:v1","training:2025-09"],
       "confidence": 0.8,
       "notes": "All metrics stable"
     }
     ```
   
   * 验收：字段完整、可解析。

8. **FR-08 系统接口（CLI/HTTP）**
   
   * CLI 示例：
     
     ```bash
     python train.py --data data.csv --model resnet --epochs 10
     ```
   
   * HTTP 示例：`POST /train` → 返回 JSON。

## D. 非功能需求（NFR）

* **可运行性**：端到端流程在本地集群可独立运行。

* **性能**：支持 1000 并发，100GB 数据训练 ≤ 30min。

* **安全性**：AES-256 数据加密，MFA 登录，RBAC 权限。

* **鲁棒性**：数据缺失、训练中断均有日志与告警。

* **维护性**：配置文件集中管理，支持 `.env` 覆盖。

功能性需求（FR）详细规格
=============

FR-01 数据管理
----------

* **描述**：支持多源数据接入与管理，包括文本、图像、音频、视频、CSV、JSON 等格式，统一存储并支持版本控制。

* **输入/输出**：
  
  * 输入：原始数据文件（CSV、JSON、图像文件等）
  
  * 输出：存储于分布式数据库的标准化数据集（带版本号）

* **前置条件**：系统已完成数据源配置并具备访问权限。

* **异常处理**：数据格式不符 → 自动校验并提示错误；文件过大 → 拆分与断点续传；重复数据 → 自动去重。

* **验收口径**：
  
  * 成功导入至少 3 种不同数据源；
  
  * 数据表包含 `id, source, version, create_time` 等统一字段；
  
  * 支持查询数据版本记录。

* * *

FR-02 数据清洗与预处理
--------------

* **描述**：对原始数据进行清洗、缺失值填补、归一化、特征工程处理，确保训练数据质量。

* **输入/输出**：
  
  * 输入：FR-01 生成的原始数据
  
  * 输出：清洗后数据集（结构化格式，字段对齐）

* **前置条件**：输入数据量可加载至分布式存储；预处理规则已配置。

* **异常处理**：缺失率 >30% → 触发告警；无效数据类型 → 丢弃并记录日志。

* **验收口径**：
  
  * 清洗前后生成对比报告（缺失率降低、异常值剔除）；
  
  * 数据维度完整性 ≥ 95%；
  
  * 用户可在 UI 查看清洗前后对比样例。

* * *

FR-03 模型训练管理
------------

* **描述**：支持 TensorFlow/PyTorch 等框架，提供模型配置、训练执行、实时监控、断点续训、模型版本管理。

* **输入/输出**：
  
  * 输入：清洗后的训练集、超参数配置
  
  * 输出：训练好的模型文件（ONNX/SavedModel）+ 训练日志

* **前置条件**：GPU/CPU 资源已分配；训练参数配置文件正确。

* **异常处理**：
  
  * 训练中断 → 自动保存 checkpoint；
  
  * GPU 内存不足 → 采用梯度累积或降 batch size；
  
  * 参数配置错误 → 返回错误码并记录日志。

* **验收口径**：
  
  * 10GB 数据集在 ≤30min 内完成训练；
  
  * 模型文件与日志均可复现；
  
  * 训练过程实时指标（loss、acc）可视化展示。

* * *

FR-04 考评任务与指标体系
---------------

* **描述**：提供自动化考评任务，包括准确率、召回率、F1、AUC、训练耗时、资源利用率等核心指标。

* **输入/输出**：
  
  * 输入：训练完成的模型与测试数据集
  
  * 输出：考评报告（JSON + PDF 格式）

* **前置条件**：模型已训练完成并存储；测试集存在。

* **异常处理**：测试集缺失 → 返回错误并中止考评；指标计算异常 → 用默认值并记录日志。

* **验收口径**：
  
  * 考评报告包含 ≥5 个核心指标；
  
  * 指标结果可与基准模型对比；
  
  * 报告存档并可导出 Excel/PDF。

* * *

FR-05 评测与反馈
-----------

* **描述**：支持自动化评测 + 人工评审结合；提供用户反馈渠道。

* **输入/输出**：
  
  * 输入：考评结果、用户反馈
  
  * 输出：更新后的考评报告、反馈存档

* **前置条件**：考评模块可用；用户具备反馈权限。

* **异常处理**：用户反馈表单缺失字段 → 拒绝提交并提示；人工评审超时 → 任务自动关闭。

* **验收口径**：
  
  * 自动化评测成功率 ≥95%；
  
  * 反馈意见存入数据库，可追溯；
  
  * 人工评审结论与自动结果整合到最终报告。

* * *

FR-06 数据分析与可视化
--------------

* **描述**：对训练与考评结果进行分析，支持趋势、对比、异常检测，并生成可视化报表。

* **输入/输出**：
  
  * 输入：训练与考评日志、指标数据
  
  * 输出：交互式仪表盘、报表（PDF/Excel）

* **前置条件**：系统已完成至少一次模型训练与考评。

* **异常处理**：数据缺失 → 使用默认值并高亮提醒；图表渲染失败 → 提示用户并保存日志。

* **验收口径**：
  
  * 仪表盘包含趋势图、对比图、异常检测曲线；
  
  * 报表可导出为 PDF 和 Excel；
  
  * 用户能交互式选择时间区间、模型版本进行对比。

* * *

FR-07 统一输出格式
------------

* **描述**：所有任务输出必须符合统一 JSON 格式，包含 `result, metrics, citations, confidence, notes` 字段。

* **输入/输出**：
  
  * 输入：任务运行结果
  
  * 输出：标准化 JSON（可导出）

* **前置条件**：任务执行成功；日志完整。

* **异常处理**：字段缺失 → 系统补齐默认值并警告；JSON 不可解析 → 自动回退为文本输出。

* **验收口径**：
  
  * 返回 JSON 必须含 5 个必选字段；
  
  * 字段含义在数据字典中定义清晰；
  
  * JSON 可通过在线校验工具解析。

* * *

FR-08 系统接口（CLI/HTTP）
--------------------

* **描述**：提供 CLI 和/或 HTTP 两种接口方式，支持训练任务启动、考评结果查询。

* **输入/输出**：
  
  * 输入（CLI）：
    
        python train.py --data data.csv --model resnet --epochs 10

* 输入（HTTP）：`POST /train`，Body 含 `data, model, params`

* 输出：统一 JSON（见 FR-07）

* **前置条件**：用户已登录并具备执行权限。

* **异常处理**：
  
  * CLI 参数缺失 → 打印帮助信息；
  
  * HTTP 请求缺字段 → 返回 400 错误码。

* **验收口径**：
  
  * CLI 成功返回结构化 JSON；
  
  * HTTP 返回 JSON，响应时间 ≤2s；
  
  * 错误码与异常日志可追溯。

功能性需求（FR）补充
===========

FR-09 考评指标校验与一致性检查
------------------

* **描述**：  
  系统需对考评报告中的数值指标进行自动校验，确保结果与基准/官方指标一致性。对比字段包括：`revenue, net_profit, solvency_ratio, total_assets, eps`。当差异 ≤ ±5% 视为一致，否则在 `notes` 字段中写入提示，并相应降低 `confidence` 值。

* **输入/输出**：
  
  * 输入：考评结果 JSON、官方指标文件（CSV）
  
  * 输出：带校验结果的 JSON（字段包括 `answer, citations, used_metrics, confidence, notes`）

* **前置条件**：
  
  * 官方指标文件已导入系统（CSV 格式，字段合法）。
  
  * 系统能解析数值类答案。

* **异常处理**：
  
  * CSV 文件缺失字段 → 报错并返回错误码；
  
  * 数值无法解析 → 将该字段标记为 `"N/A"` 并写入日志；
  
  * 指标超出容差范围 → 自动写入 `notes` 并降低 `confidence`。

* **验收口径**：
  
  * 在样例数据中，`AIA/2023` 的净利润值若与官方指标差异 10%，系统自动在 `notes` 标注 `"Mismatch with official metrics"`，并将 `confidence` 降至 ≤0.7；
  
  * ±5% 容差内的指标需标记为一致；
  
  * 输出 JSON 符合以下格式示例：
    
        {
          "answer": "公司2023年净利润为100亿元",
          "citations": ["AIA:2023:p12"],
          "used_metrics": ["net_profit"],
          "notes": "Mismatch with official metrics",
          "confidence": 0.68
        }

FR-10 系统入口形式（CLI / HTTP 服务）
---------------------------

* **描述**：  
  系统需至少支持一种标准化入口（CLI 或 HTTP 服务），用于提交训练/考评任务并返回统一 JSON 输出。

* **输入/输出**：
  
  * **CLI 方案**：
    
    * 输入：
      
          python app.py --task train --data data.csv --model resnet --epochs 10

    * 输出：标准 JSON 文件打印到 stdout。

* **HTTP 方案**：
  
  * 输入：
    
        POST /train
        Content-Type: application/json
        {
          "data": "data.csv",
          "model": "resnet",
          "params": {"epochs":10}
        }

    * 输出：JSON 响应（字段同 FR-07）。

* **前置条件**：
  
  * 系统已部署在可执行环境（命令行或 HTTP 服务）。
  
  * 用户具备执行权限并完成身份认证。

* **异常处理**：
  
  * CLI 参数缺失 → 打印帮助文档 `--help`；
  
  * HTTP 请求缺字段 → 返回 `400 Bad Request`；
  
  * 服务不可用 → 返回 `503 Service Unavailable` 并写日志。

* **验收口径**：
  
  * CLI 运行成功时，标准输出为 JSON 且字段完整；
  
  * HTTP 调用成功时，响应时间 ≤2 秒，返回 JSON 中 `citations` 数组非空；
  
  * 错误码包含 400/401/500，异常语义明确。
