《AI大模型数据训练系统平台测试方案（含用例）》
========================

A. 测试目标、范围与不测清单
---------------

### 目标

1. 验证系统 **10项核心能力**：数据采集、预处理、索引、检索、Prompt构建、LLM调用、结果解析、指标校验、接口、自动化评测。

2. 验证输出的 **结构化JSON** 符合统一规范（answer/citations/used_metrics/confidence/notes）。

3. 验证系统在 **CPU/离线/不可联网/不可微调** 条件下，能端到端稳定运行。

### 范围

* 数据类型：PDF（财报）、CSV（指标表）、JSONL（query集）。

* 模型：MockLLM，CPU单机执行。

* 核心流程：Loader→Cleaner→Chunker→Indexer→Retriever→Promptor→LLM→Parser→Guardrail→CLI/Eval。

### 不测清单

* 不涉及真实商用LLM联网调用。

* 不测大规模分布式集群部署性能。

* 不测UI前端可视化交互。

* * *

B. 环境与数据准备
----------

| 类别  | 配置                                                                                                                                                   |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 硬件  | Ubuntu 22.04, Intel Xeon 32核, 128GB RAM, SSD 2TB                                                                                                     |
| 软件  | Python 3.10, PyTorch 2.1, FAISS, Flask, Scikit-learn                                                                                                 |
| 限制  | **禁网**, 仅CPU执行, 不可微调                                                                                                                                 |
| 数据  | - `data/reports/*.pdf`（3份，SHA256校验）- `data/tables/key_metrics.csv`（含 revenue/net_profit/solvency_ratio 等字段）- `data/queries/dev_set.jsonl`（500条query） |
| 向量库 | `data/vector_store`，需验证 **首次构建/再次加载** 两种路径                                                                                                           |

* * *

C. 测试策略与覆盖
----------

1. **层级策略**
   
   * 单元：Loader/Parser/Chunker
   
   * 组件：Retriever+Indexer、Promptor+LLM
   
   * 集成：检索→Prompt→LLM→解析
   
   * 端到端：CLI批跑 & Eval批跑
   
   * 回归：每次需求变更后运行Eval

2. **覆盖设计**
   
   * 正向功能：解析/检索/输出完整性/指标校验
   
   * 异常场景：CSV缺列、空检索、索引损坏、长上下文截断、JSON解析失败
   
   * 边界条件：BM25开关、Top-k变化、Chunk大小 500 vs 1000

3. **数据充分性**
   
   * PDF页码覆盖率≥90%
   
   * CSV字段覆盖完整
   
   * dev_set 500条全量跑

4. **输出规范检查**
   
   * 独立设计用例校验 JSON 字段完整性
   
   * 验证 citations 来源匹配 PDF 文档

5. **指标校验链**
   
   * extract→compare→±5% 容差→notes/confidence 调整

* * *

D. 通过/退出准则与量化阈值
---------------

| 维度      | 阈值                                     |
| ------- | -------------------------------------- |
| 可运行性    | E2E跑通率 100%，无致命异常                      |
| 检索相关性   | Top-5命中率 ≥85%                          |
| 回答完整性   | JSON字段完整率 100%，citations 非空            |
| 引用准确性   | ≥90%                                   |
| 指标校验正确性 | ±5%内一致率 ≥90%，不一致需降 confidence 并写 notes |
| 异常鲁棒性   | 异常用例通过率 ≥95%                           |

* * *

H. 风险、优先级与回归策略
--------------

* **风险**：PDF解析不稳、CSV缺列、索引损坏、Mock与真实LLM差异、长上下文截断。

* **优先级**：
  
  * P0：可运行性、结构化输出、引用准确性、指标校验
  
  * P1：混检效果、检索命中率
  
  * P2：性能优化

* **回归策略**：所有P0/P1缺陷修复后必须回归验证；Eval统计需对比修复前后指标。
